## Abstract (verbatim)

In compiler research, polytopes and related mathematical objects have been successfully used for several decades to represent and manipulate computer programs in an approach that has become known as the polyhedral model. The key insight is that the kernels of many compute-intensive applications are composed of loops with bounds that are affine combinations of symbolic constants and outer loop iterators. The iterations of a loop nest can then be represented as the integer points in a (parametric) polytope and manipulated as a whole, rather than as individual iterations. A similar reasoning holds for the elements of an array and for mappings between loop iterations and array elements.

**Keywords (publisher-assigned):** Integer Point, Basis Reduction, Vertex Enumeration, Polyhedral Model, Rational Polyhedron.

## Summary (not verbatim — for orientation)

`isl` is an open-source C library for manipulating sets and relations of integer points bounded by affine constraints — the core data structures of the polyhedral model. It is the computational substrate underneath much of the modern polyhedral-compilation ecosystem (it is used by PPCG, Polly/LLVM, GCC/Graphite, Tiramisu, and others), which is why it is essential reading for anyone implementing a polyhedral flow rather than merely studying one.

The library represents **(parametric) sets** — e.g. a statement's iteration domain `{ S[i,j] : 0 ≤ i < N ∧ 0 ≤ j < M }` — and **(parametric) binary relations** — e.g. access relations mapping iterations to accessed array elements, dependence relations, and scheduling/scattering maps. Both are *quasi-affine*: constraints may involve integer division and modulo, and may be parameterized by symbolic constants. Sets and maps are maintained as unions of convex pieces, so the library handles the non-convex objects that arise in real programs.

Operations provided include the standard set/relation algebra (intersection, union, difference, projection, application of a relation to a set, composition of relations), emptiness and equality tests, convex hull and (affine) hull, coalescing of unions, and **parametric integer programming** (lexicographic optimization) — the engine used to compute exact dataflow dependences and to solve the integer linear programs that arise in affine scheduling (as in PLUTO and the isl scheduler). It also computes **transitive closures** of affine relations (approximated when exact closure is not affine), performs **vertex enumeration** and counting of the integer points in a parametric polytope (Ehrhart-style), and supports **integer affine basis reduction**. Internally it relies on exact (GMP-based) integer arithmetic and on a tightly integrated implementation rather than coordinating separate libraries, which the paper argues gives both robustness and performance advantages over earlier toolchains (Omega, PolyLib, PPL, etc.).

For a transpiler project, the practical relevance is: iteration domains, access relations, and schedules are all `isl` objects; legality checking of a transformation reduces to emptiness tests on dependence relations; fusion/tiling/skewing are expressed as new schedule maps; and code generation (via the companion isl AST generator / CLooG) consumes these maps directly.
